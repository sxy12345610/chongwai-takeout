# 重外校园外卖平台 · 迁移实施计划

> 文档版本：v0.1（第一阶段：架构审计与设计）
> 原则：**最低风险、可随时回退、不丢失现有功能与静态资源**
> 当前状态：现有项目为可运行的 Vue 3 + Vite 前端演示版（LocalStorage），管理后台已完成

---

## 1. 迁移总原则

1. **不推倒重来**：现有 `src/`、`public/`、`vite.config.js` 原位保留，继续可运行。
2. **管理端优先保留**：现有 Vue 3 管理后台作为 Web 管理端基础，逐步从 LocalStorage 切换到真实 API。
3. **后端先行、前端后接**：先建立数据库与 API，再逐页替换数据源。
4. **小程序最后做**：uni-app 端在 API 稳定后开发，复用现有页面结构与样式。
5. **每一步可回退**：每个阶段结束都应保持「旧版可运行」。
6. **不破坏 URL 与用户数据**：现有 Hash 路由、图片路径、演示数据保留。
7. **真实支付最后接**：先用「待支付 + 模拟完成」跑通业务，再评估商户号。
8. **文档与代码同步**：数据库/API 变更必须更新 `docs/`。

## 2. 目标目录与迁移方式

目标结构：

```
chongwai-takeout/
├── apps/
│   ├── admin/          # 现有 Vue 3 管理端（从根目录迁入或保持根目录）
│   └── miniapp/        # uni-app + Vue 3 微信小程序
├── server/             # Node.js + Express + Prisma
├── packages/
│   └── shared/         # 共享常量、类型、工具（可选）
├── docs/
└── public/images/      # 现有静态资源
```

**迁移策略**：

- 第一阶段**不移动文件**。现有根目录继续作为 admin 端运行。
- 待后端稳定后，再将根目录前端迁入 `apps/admin`（或保留根目录，仅新增 `apps/miniapp`）。
- 静态图片保留在 `public/images`，小程序端通过后端返回的 URL 或复制到小程序静态目录引用。
- 是否采用 monorepo（pnpm workspace）**待确认**；若担心风险，可先不引入 workspace，仅新增 `server/`。

## 3. 阶段划分（按风险从低到高）

### 阶段 0：基线冻结与备份（当前）

**目标**：确保迁移前有可回退基线。

任务：

1. 初始化 Git 仓库（当前项目目录**没有** `.git`），提交现有完整代码。
2. 打标签 `v0.1-demo`（纯前端演示版）。
3. 确认 `npm run build` 通过、`public/images` 完整（dishes 36 张、shops 6 张）。
4. 记录现有 LocalStorage 键与数据结构（见 `docs/code-audit.md`）。

验收：

- 构建产物可正常打开；

---

### 阶段 1：后端骨架与数据库（无前端改动）

**目标**：跑通服务、建库、种子数据，前端仍用 LocalStorage，不受影响。

任务：

1. 整理/重建 `server/`（Express + Prisma）。
2. `schema.prisma` 按 `docs/database.md` 落地（14 张核心表）。
3. 本地 PostgreSQL（Docker 或本机）建库，执行首次 migration。
4. 编写 seed：6 商家、6 分类、36 商品、演示账号（密码走环境变量）。
5. 实现健康检查 `/healthz`、`/readyz`、统一错误处理、日志。
6. 实现 JWT 认证中间件与角色守卫（USER / MERCHANT / RIDER / ADMIN）。
7. 提供只读接口：商家列表、商家详情、商品列表、分类。

验收：

- `GET /healthz` 返回 200；
- 数据库表结构与文档一致；
- 只读接口返回种子数据；
- 现有前端 `npm run build` 仍通过。

风险：低。数据库与前端完全隔离。

---

### 阶段 2：核心业务 API（用户 / 地址 / 购物车 / 订单）

**目标**：后端具备完整下单能力，前端暂不切换。

任务：

1. 微信登录（可先用开发态 mock openid，真实 `code2Session` 后接）。
2. 地址 CRUD + 默认地址唯一。
3. 购物车 CRUD + 跨商家分组。
4. 结算预览、创建订单（拆单、服务端计价、库存扣减、快照）。
5. 订单列表/详情/取消。
6. 商家接单/拒单/出餐。
7. 统一业务错误码与幂等（`Idempotency-Key`）。
8. 编写接口测试（可用 Supertest）覆盖：拆单、金额、库存、越权。

验收：

- 通过 API 可完成「加购 → 下单 → 商家接单 → 出餐」全流程；
- 跨商家购物车生成多笔订单且金额正确；
- 越权访问返回 403；
- 库存不足返回 3004。

风险：中。重点在金额与库存，必须服务端计算、事务处理。

---

### 阶段 3：现有 Vue 管理端接入真实 API

**目标**：保留现有页面，逐页替换 LocalStorage 数据源。

顺序（每页独立可回退）：

1. `AdminShops.vue` → `GET/PATCH /merchant/profile`、营业开关。
2. `AdminProducts.vue` → `/merchant/products` CRUD、上下架、库存。
3. `AdminOrders.vue` → `/merchant/orders`、接单/拒单/出餐。
4. `Admin.vue` / `AdminStatistics.vue` → `/merchant/stats/*`。
5. 登录页与路由守卫：`/admin` 未登录跳转登录；按角色显示菜单。
6. 移除后台对 LocalStorage 的写入，保留只读兜底开关（开发演示用）。

验收：

- 后台所有操作落库，刷新不丢失；
- 学生端（暂仍 LocalStorage）与后台不再共享数据，需明确提示；
- 构建通过、无控制台报错。

风险：中。页面结构可复用，主要是数据层替换与鉴权。

---

### 阶段 4：学生端 Web 版接入 API（过渡）

**目标**：在开发 uni-app 前，先让现有 Web 学生端用上真实 API，验证契约。

任务：

1. 封装 `src/api/` 请求层（axios/fetch + Token 拦截 + 错误提示）。
2. 用户登录/资料/地址接入。
3. 商家列表/详情/商品接入。
4. 购物车接入（登录后同步；未登录可本地临时车）。
5. 结算/下单接入（去掉前端算钱与模拟支付，改为待支付）。
6. 订单列表/详情/取消接入。
7. 保留演示开关 `VITE_USE_MOCK=true` 可回退 LocalStorage。

验收：

- Web 端可完成真实下单（未支付状态）；
- 金额与后端一致；
- 刷新、换设备数据不丢失。

风险：中。此阶段解决所有前后端契约问题，为小程序铺路。

### 阶段 5：uni-app 微信小程序端

**目标**：新增小程序客户端，复用现有 UI 与业务规则。

任务：

1. 初始化 `apps/miniapp`（uni-app + Vue 3 + Vite）。
2. 迁移页面：首页、商家列表、商家详情、购物车、确认订单、订单列表/详情、个人中心、地址。
3. 适配小程序：`rpx`、安全区、`scroll-view`、图片域名白名单。
4. 微信登录 `wx.login` → `/auth/wx-login`。
5. 接入支付（若商户号就绪）：预支付 + `wx.requestPayment` + 轮询。
6. 订阅消息（订单状态变更）可选。
7. 与 Web 端共享同一套 API 与数据库。

验收：

- 微信开发者工具可完整走通「登录 → 浏览 → 下单 → 支付（或待支付）→ 查看订单」；
- 真机预览无白屏、无图片 403；
- 与 Web 端数据一致。

风险：高。小程序限制多（域名白名单、包体积、支付资质），需预留联调时间。

## 4. 风险清单与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 无微信商户号 | 无法真实支付 | 先做「待支付」闭环，支付开关关闭；不伪造成功 |
| 多商家结算合规 | 资金风险 | 优先服务商分账；否则平台统一收款 + 人工结算 |
| 前后端契约不一致 | 返工 | 阶段 4 先用 Web 端验证全部 API |
| 金额计算不一致 | 资损/纠纷 | 服务端唯一计价；前端只展示；下单忽略前端金额 |
| 库存超卖 | 履约失败 | 条件更新扣减；事务；不足即失败 |
| 越权访问 | 数据泄露 | 服务端强制归属校验；不接受前端 merchantId/userId |
| 小程序图片域名限制 | 图片不显示 | 后端统一图片 URL；配置 downloadFile 合法域名 |
| 现有功能丢失 | 比赛演示失败 | 每阶段保留 `v0.1-demo`；特性开关可回退 |
| Git 误操作 | 代码丢失 | 项目目录单独初始化仓库；不在用户主目录 `git add -A` |
